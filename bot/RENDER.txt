============================================================
КАК ПОДНЯТЬ БОТА НА RENDER
============================================================

ПОЧЕМУ РАНЬШЕ НЕ РАБОТАЛО

Токен лежал строкой прямо в bot/bot.py. Чтобы он не попал в
публичный репозиторий, вся папка bot была спрятана в .gitignore.
А Render берёт код из репозитория — и получалось, что запускать
ему нечего. Отсюда «Not Found».

Теперь токен вынесен в отдельный файл bot/token.txt. Прячется
только он, а код бота спокойно едет в репозиторий.


------------------------------------------------------------
ШАГ 1. Отправить код на GitHub
------------------------------------------------------------

В папке сайта, в терминале:

    git add .
    git commit -m "Бот: токен вынесен из кода, готов к Render"
    git push

Проверьте на GitHub, что папка bot появилась, а файла
bot/token.txt в ней НЕТ. Если token.txt виден — остановитесь
и напишите мне, разберёмся.


------------------------------------------------------------
ШАГ 2. Создать сервис на Render
------------------------------------------------------------

1. render.com → New → Blueprint
2. Выбрать репозиторий classixtreet
3. Render сам прочитает файл render.yaml в корне и предложит
   создать сервис classixtreet-bot
4. Он спросит значение BOT_TOKEN — вставьте туда токен
   (тот же, что в bot/token.txt)
5. Create

Если Blueprint не предлагается — New → Web Service, и вручную:
    Build Command:  pip install -r bot/requirements.txt
    Start Command:  python bot/bot_webhook.py
    Environment:    BOT_TOKEN = <ваш токен>
                    ADMIN_CHAT_ID = 1429396337
                    WEBAPP_URL = https://classixtreet.store/app.html


------------------------------------------------------------
ШАГ 3. Проверить
------------------------------------------------------------

Откройте адрес сервиса в браузере. Должна быть строка:

    CLASSIXTREET бот работает

В логах Render при запуске должно быть:

    бот @classixtreet_photo_bot
    вебхук поставлен: https://…onrender.com/

Если вебхук не поставился — значит Render не передал свой
адрес. Задайте переменную RENDER_EXTERNAL_URL вручную.


------------------------------------------------------------
ШАГ 4. Указать адрес сайту
------------------------------------------------------------

Render даст адрес вида https://classixtreet-bot-xxxx.onrender.com
Он может отличаться от старого. Впишите его в js/cart.js:

    var ORDER_API = 'https://ВАШ-АДРЕС.onrender.com/api/order';

И добавьте адрес сайта в bot/bot_webhook.py в список
ALLOWED_ORIGINS, если он изменится.

Потом снова git push — и заказы с сайта поедут.


============================================================
ЧТО НУЖНО ЗНАТЬ ПРО БЕСПЛАТНЫЙ RENDER
============================================================

1. ЗАСЫПАЕТ. После 15 минут без запросов сервис выключается,
   и следующий запрос будит его 30–60 секунд. Сайт это
   переживёт — он ждёт до полутора минут и пишет покупателю,
   что идёт отправка. Но первый заказ после паузы будет
   медленным.

   Лечится бесплатно: cron-job.org, задание раз в 10 минут
   открывать адрес сервиса. Тогда он не уснёт. Бесплатных
   часов Render на это хватает.

2. ФАЙЛЫ НЕ ХРАНЯТСЯ. Диск на Render временный: при каждом
   перезапуске папка bot/orders очищается. Заказ в Telegram
   останется навсегда, а файл — нет. Считайте настоящим
   архивом переписку с ботом, а не папку.

3. ПУБЛИКАЦИЯ ФОТО НА САЙТ ОТТУДА НЕ РАБОТАЕТ. Команда /ok
   переносит фото в img/gallery и дописывает строку в
   js/gallery.js — то есть меняет файлы сайта. На Render эти
   файлы временные и в репозиторий не попадают, так что до
   сайта фото не доедет.

   Приём фото и модерация работают, теряется только последний
   шаг. Пока фото добавляйте на сайт руками. Если это нужно
   автоматически — скажите, сделаю так, чтобы бот отправлял
   фото не в файл, а коммитом в репозиторий.

4. ОДИН БОТ — ОДИН СПОСОБ СВЯЗИ. Пока на Render стоит вебхук,
   запускать bot.py на компьютере через .bat нельзя: они будут
   мешать друг другу. Либо там, либо здесь.
